# AI-OS Phase 4.5 — Voice Design

**Date:** 2026-06-12
**Status:** Approved (brainstorm complete, awaiting implementation plan)
**Parent spec:** `2026-06-11-cognitive-kernel-design.md` (roadmap addendum in
`2026-06-12-phase4-heartbeat-design.md`)

## Summary

Voice in and out on every surface, fully local: Telegram voice notes are transcribed
(whisper.cpp) and routed like any text message, with replies returned as synthesized
voice notes (kokoro-js, macOS `say` fallback); the Mission Control cockpit gets a
click-to-toggle mic with spoken replies. Audio never leaves the Mac; no API keys.

## Requirements (from brainstorm)

| Dimension | Decision |
|---|---|
| Engines | Fully local: whisper.cpp STT (brew), kokoro-js TTS (npm, ONNX) with macOS `say` fallback. No keys, no cloud. |
| Reply policy | Mirror: voice in → voice note reply (+ text transcript both directions); text in → text only |
| Cockpit interaction | Click-to-toggle mic button in the Chat view (pulse while recording, click to send) |
| Architecture | Central `VoiceService` (`transcribe`/`synthesize`) consumed at the edges (Telegram adapter, web endpoint, mirror logic in index) — router untouched |

## Architecture — voice is edge transcoding

```
Telegram voice note ──► telegram.ts (message:voice) ──► download OGG
                                                          │
Cockpit mic ──► MediaRecorder (webm) ──► POST /api/voice ─┤
                                                          ▼
                                              VoiceService.transcribe()
                                              (ffmpeg → wav 16k → whisper-cli)
                                                          │ text
                                                          ▼
                                          existing router.handle() — unchanged
                                                          │ reply text
                                                          ▼
                                          voice-in? ──► VoiceService.synthesize()
                                                          │
                            Telegram: sendVoice + text ◄──┴──► Cockpit: audio + text
```

- **Router untouched.** By the time a message hits routing it is text. Moderator,
  finance, gate commands (`/approve` spoken aloud), and triage all work with voice
  for free.
- **Mirror state lives at the entry edge** — each consumer remembers "this exchange
  was voice" and synthesizes the reply it receives.
- **Transcripts always visible** — voice replies carry their text; history stays
  searchable.
- **Graceful degradation** — voice failing or missing never breaks text.

## VoiceService (`src/voice/`)

Three files:

### `stt.ts` — `transcribe(audioPath): Promise<string>`

1. `ffmpeg -i in -ar 16000 -ac 1 out.wav` (handles Telegram OGG/opus, browser webm,
   anything).
2. `whisper-cli -m data/models/<model>.bin -f out.wav` → transcript.
3. Temp files in `data/voice-tmp/`, cleaned per call.

Model: `ggml-base` default (~150 MB, fast, good multilingual);
`AIOS_WHISPER_MODEL` swaps (`base|small|medium`). Auto-downloaded from HuggingFace
into `data/models/` on first use (size sanity check; interrupted downloads cleaned
and retried on the next call). Download failure → voice stays disabled with a clear
log line.

### `tts.ts` — `synthesize(text): Promise<string>` (returns audio file path)

- Primary: `kokoro-js` (ONNX runtime, model auto-downloads ~80 MB on first use,
  near-human; `AIOS_TTS_VOICE` selects the voice).
- Fallback: macOS `say -o out.aiff` + ffmpeg → OGG (zero deps, robotic, never
  fails). `AIOS_TTS_VOICE=say` forces it.
- Long-text guard: replies over 3000 chars synthesize the first 3000 + "…full text
  below" (full text is always sent alongside anyway).

### `index.ts` — `VoiceService`

Wires both engines; `available(): boolean` from a boot-time probe
(`which whisper-cli ffmpeg` + model presence/downloadability). The disabled reason
is logged once at boot. Transcriptions are serialized through a simple in-process
queue (one whisper process at a time — parallel spawns thrash memory; base model
runs ~1 s per 10 s of audio on M-series).

Engine swaps (cloud STT/TTS later, Kokoro upgrades) touch only this module.

## Telegram integration

**Inbound** — new `message:voice` handler (mirrors the existing document/photo
handler):

1. Download OGG via the existing `getFile` flow into `data/downloads/`.
2. `voice.transcribe(path)` → transcript.
3. Send `🎙 "<transcript>"` back immediately — the user sees what was heard before
   the answer arrives (mis-transcriptions surface instantly).
4. Forward as a normal `InboundMessage` with `text = transcript` and `voiceIn: true`.
5. Transcription failure → "Couldn't transcribe that — try again?" (no routing).

**Outbound** — `ChannelAdapter` gains optional
`sendVoice?(chatId, audioPath, caption)`. Telegram implementation uses the
`sendVoice` API with the transcript as caption; captions over Telegram's 1024-char
limit fall back to voice note + separate text message.

**Mirror wiring** (in `index.ts` `onMessage`): `msg.voiceIn` && reply non-null →
`synthesize(reply)` → `ch.sendVoice(...)`; synthesis failure → plain text send.
Voice works in bound group chats (finance) — same path, transcript routes to the
bound agent.

**`InboundMessage`** gains `voiceIn?: boolean`. Only channels and the index mirror
logic read it; the router ignores it.

## Cockpit voice

**API** — `POST /api/voice` (inside the existing bearer-token guard):

- Body: raw audio bytes (`Content-Type: audio/webm`), 25 MB cap.
- Query `target` — same semantics as `/api/chat` (moderator/finance/@role).
- Flow: temp file → transcribe → `router.handle({channel:"web", chatId:"ui", text})`
  → synthesize reply → JSON `{ transcript, reply, audio: <base64 OGG> }` (single
  round trip; no file-serving endpoints; voice replies are < 1 MB/min).
- Voice unavailable → `503 { error: "voice disabled: <reason>" }`.
- `/api/state` gains a `voice: boolean` field; the UI hides the mic when false.

**UI (`ui/src/views/Chat.tsx`)** — mic button beside the input:

- Click → `MediaRecorder` (`audio/webm;codecs=opus`), button pulses; click again →
  stop + POST.
- Response appends `🎙 <transcript>` as the user message + the reply to the log;
  reply audio auto-plays (data-URI `Audio`) with a replay button.
- Mic permission is browser-native; `localhost` and Tailscale HTTPS are both secure
  contexts.

## Config additions

```
AIOS_WHISPER_MODEL=base        # base|small|medium — ggml model name
AIOS_TTS_VOICE=af_heart        # kokoro voice id; "say" forces the macOS fallback
AIOS_VOICE_ENABLED=true        # kill-switch
```

Setup: `brew install whisper-cpp ffmpeg`; `kokoro-js` added to package.json. Models
auto-download on first use.

## Error handling — voice never breaks text

- Boot probe fails → one warning, `available() = false`, mic hidden, Telegram voice
  notes answered with "voice processing unavailable".
- Transcribe failure → friendly retry message, nothing routed.
- Synthesize failure → text-only reply (mirror silently downgrades).
- Interrupted model download → partial file cleaned, retried next call.
- Whisper queue serialized; temp files cleaned per call; `data/voice-tmp/` swept at
  boot.

## Security notes

- All subprocess invocations use `execFile` (argument arrays) — never `exec` with
  interpolated strings; file paths are internally generated, user content stays in
  file BODIES, not command lines.
- The web endpoint sits behind the existing `AIOS_UI_TOKEN` guard and a 25 MB body
  cap.
- Audio and transcripts never leave the machine.
